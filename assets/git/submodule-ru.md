# Git Submodules: Полное руководство

Это руководство охватывает лучшие практики управления подмодулями Git, включая высокопроизводительное клонирование, обновление и правильное (чистое) удаление.

## 1. Клонирование проекта с подмодулями

### Сценарий А: Клонирование с нуля (Самый быстрый способ)
Если вы клонируете репозиторий впервые, используйте эту команду «все-в-одном». Она клонирует основной репозиторий и параллельно скачивает последние версии подмодулей без лишней истории изменений.

```bash
git clone --recurse-submodules --shallow-submodules --jobs 10 <URL_репозитория>
```
*   `--recurse-submodules`: Автоматически инициализирует и клонирует вложенные подмодули.
*   `--shallow-submodules`: Клонирует подмодули с параметром `depth 1` (экономит время и трафик).
*   `--jobs 10`: Скачивает до 10 подмодулей параллельно.

### Сценарий Б: Проект уже склонирован (Инициализация)
Если вы уже склонировали репозиторий, но папки подмодулей пусты:

```bash
# Быстрая инициализация (скачивается только последний коммит)
git submodule update --init --recursive --jobs 10 --depth 1
```

## 2. Добавление подмодуля

### Через командную строку (Рекомендуется)
Это самый надежный способ.

```bash
# Синтаксис: git submodule add <ссылка> <путь/к/папке>
git submodule add https://github.com/example/repo.git libs/my-lib

# Опционально: Если нужно отслеживать конкретную ветку (например, main)
git submodule add -b main https://github.com/example/repo.git libs/my-lib

# Зафиксируйте изменения
git commit -m "Добавлен подмодуль: libs/my-lib"
git push
```

### Через IntelliJ IDEA
1. Откройте окно **Git** (`Alt+9` / `Cmd+9`).
2. Нажмите правой кнопкой на корень проекта -> **New** -> **Module from Existing Sources** (или **Git** -> **Manage Projects** в зависимости от версии).
3. *Лучшая альтернатива:* Просто откройте встроенный терминал в IDEA и выполните команды, указанные выше.

## 3. Обновление подмодулей

Существует два сценария обновления. Выберите тот, который подходит под вашу задачу.

### Вариант А: Синхронизация (Как в основном репозитории)
Используйте этот вариант, когда ваши коллеги обновили версию подмодуля в основном проекте, и вы хотите синхронизировать свой локальный проект с их изменениями.

```bash
git submodule update --recursive --jobs 10
```

### Вариант Б: Апгрейд (Получение свежих изменений из удаленной ветки)
Используйте этот вариант, если вы хотите принудительно обновить подмодуль до самого последнего коммита из его удаленной ветки (например, `main` или `master`).

```bash
# 1. Скачать последние изменения для подмодулей
git submodule update --remote --merge --jobs 10

# 2. Зафиксировать новую версию в основном репозитории
git add <путь/к/подмодулю>
git commit -m "Обновление подмодуля до последней версии"
```

## 4. Удаление подмодуля (Чистое)

Неправильное удаление подмодуля может оставить «призрачные» конфигурации. Следуйте этим шагам для полного удаления.

### Шаг 1: Деинициализация (Отмена регистрации)
Эта команда автоматически удаляет подмодуль из `.git/config`.
```bash
git submodule deinit -f <путь/к/подмодулю>
```

### Шаг 2: Удаление записи и файлов
Удаляет запись из файла `.gitmodules` и саму папку из рабочей директории.
```bash
git rm -f <путь/к/подмодулю>
```

### Шаг 3: Очистка внутренней директории Git
Git хранит копию метаданных подмодуля в папке `.git/modules`. Её нужно удалить, чтобы избежать конфликтов, если вы решите добавить этот подмодуль снова позже.

**Linux / macOS / Git Bash:**
```bash
rm -rf .git/modules/<путь/к/подмодулю>
```

**Windows (PowerShell):**
```powershell
Remove-Item -Recurse -Force .git/modules/<путь/к/подмодулю>
```

### Шаг 4: Фиксация изменений
```bash
git commit -m "Удален подмодуль <путь>"
git push
```

## 5. Советы и решение проблем

### Состояние "Detached HEAD"
Подмодули обычно указывают на конкретный хеш коммита, поэтому они находятся в состоянии "Detached HEAD" (оторванный HEAD). Это нормально.
Если вам нужно внести изменения **внутри** подмодуля:
1. `cd <папка_подмодуля>`
2. `git checkout main` (или ваша ветка)
3. Внесите изменения -> Commit -> Push.
4. Вернитесь в корень основного проекта -> Закоммитьте обновление ссылки на подмодуль.

### Ограничения "поверхностного" (Shallow) клонирования
Если вы использовали `--depth 1` (или `--shallow-submodules`), команда `git log` внутри подмодуля покажет только один коммит. Если вам понадобится полная история позже, выполните внутри папки подмодуля:
```bash
cd <путь/к/подмодулю>
git fetch --unshallow
```
